### 3.2 The session state machine is a real correctness bug, not a nice-to-have

`internal/api/handlers.go:985-1008` on `main`:

```go
if err := httpx.DecodeJSON(r, &req); err != nil || !validSessionStatus(req.Status) {
	httpx.WriteError(w, http.StatusBadRequest, "invalid status")
	return
}
if err := h.sess.UpdateStatus(r.Context(), id, req.Status); err != nil { ... }
```

`validSessionStatus` is a flat whitelist. There is no `from → to` check. Consequences:

- A client can `PATCH` a freshly-created session straight to `completed` without playing a single second.
  That silently corrupts **session completion** — the #3 primary product metric (§68) and the headline number
  on the admin dashboard (§6).
- `completed` → `playing` is accepted. There is no terminal state.
- The 11-state vocabulary in §15 (`DRAFT READY SCHEDULED STARTING ACTIVE PAUSED INTERRUPTED COMPLETED
  CANCELLED EXPIRED FAILED`) is not modelled at all — only 4 values exist.

Notably, `mvp-phase`'s missing `internal/sessions` package was *attempting exactly this fix*
(`sessions.CanTransition`, `sessions.Reason`). The intent was right; the code was never committed.

## 4. KEEP / REFACTOR / REPLACE / DELETE / ADD

### KEEP (do not touch)
- All of `main`'s backend: auth, MFA, profile, deletion/export, entitlements, rights, storage/signing,
  scheduler, push, ratelimit, jobs, metrics, health. 348 passing tests.
- `internal/deletion`'s policy-completeness guard test. It is already earning its keep.
- `contracts/openapi.json` (70 paths / 97 ops) and the route-table-driven OpenAPI generator.
- `clients/dart` — it is the correct seed for the Flutter app's networking layer.

### REFACTOR
- `updateSessionStatus` → route through a real state machine (see ADD).
- `internal/store` and `internal/db` have **0% direct test coverage**; add store-level tests.
- `internal/config` at 25.9% and `internal/auth` at 32.2% are thin for security-critical code.

### REPLACE
- SQLite-only runtime → dual-driver with real Postgres support (§49).
- Embedded `webapp/index.html` → Next.js public site (§5).
- Embedded `adminui/index.html` → Next.js admin (§6). Keep the Go-served HTML as a fallback/ops console only.
- `migrations/postgres/0001_schema.sql` → regenerate from the SQLite schema of record, then drive both
  dialects from one source of truth.

### DELETE
- `server/.env.examplemp_audio_debug.go`
- `iconfess-phase0-1.patch` (mvp-phase)
- `client/me` (mvp-phase)
- `APPLY_ICONFESS.ps1` / `PUSH_ICONFESS.ps1` — decide; these are Windows-only apply scripts that duplicate git.

### ADD (priority order)
1. **`internal/sessions`** — the state machine. Unblocks `mvp-phase`, fixes the metric-corruption bug, satisfies §15.
2. **Duration strategies in `internal/engine`** — `Strategy`, `IsValidStrategy`, `Request.Duration/Strategy`, satisfies §17.
3. **Deletion policies** for the 6 new tables.
4. **Postgres driver + migration parity** (§49).
5. **The 38 categories** as a real seed/migration, not a 16-item subset (§7).
6. **`README.md`** — currently 1 byte.
7. **Next.js web + admin, Flutter app** (§4–§6).

## 5. Recommended sequence

`mvp-phase` must not be merged as-is: it does not compile. Two sane paths:

**Path A — repair then merge (recommended).** Write the missing `internal/sessions` state machine and the
engine `Strategy` layer on a branch off `main`, add the 6 deletion policies, then merge `mvp-phase` and prove
`go build && go vet && go test ./...` green. Nothing in `mvp-phase`'s backend additions is lost.

**Path B — cherry-pick.** Take `mvp-phase`'s schema, migrations, docs and store code onto `main` and discard
the non-compiling `ai/`, `billing/`, `cache/`, `community/`, `tracing/` packages until they compile.
Faster to green, but throws away committed work.
