# Verify private media delivery in staging

**Release gate, not a test result.** This applies to the [S3 + CloudFront stack](../infrastructure/media-cloudfront.yaml). The backend Deploy workflow does not update that stack. CI checks the template, signer and operator check **offline**; none of those checks establishes what a deployed edge or a listener's cache is doing.

| Viewer path | Required CloudFront behavior |
| --- | --- |
| `audio/voices/*` (governed masters and variants, including editorial), `voice-private/*` (source material), `bible/*` (rights-controlled media) | HTTPS only; trusted key group; **Managed-CachingDisabled** at the edge. Override the viewer's `Cache-Control` with `private, no-store`, including for objects uploaded with `public, immutable` metadata. |
| Default (e.g. `audio/content/*`) | Same trusted key group and private S3 origin; **Managed-CachingOptimized**. A cache hit does not dispense with viewer signature validation. |

A successful app authorization is what permits **issuing** a URL. The CDN checks possession and expiry, not accounts, minister-voice consent, or current publication rights. None of these patterns is a new signing entitlement. If intake material is in a **separate unrouted bucket**, keep it there; do not attach it to a CDN to run this check.

## 1. Confirm the actual route

1. Use an approved **staging** stack, account, region and operator profile. Compare the API's `S3_BUCKET`, region, `MEDIA_BASE_URL` and public `CLOUDFRONT_KEY_PAIR_ID` to that stack's outputs. The media URL must be the bare HTTPS distribution origin or its TLS-enabled alias, with no path prefix, nonstandard port, credentials, query or fragment (`:443` and a trailing slash are normalized). Confirm DNS actually routes the API's media hostname to this distribution. Do not copy, print or upload a private key.
2. Review the stack change set: update the distribution in place, not the bucket, origin, or signing identity. Keep S3 Block Public Access, encryption, versioning, the OAC (`always`/SigV4) and the distribution-scoped `s3:GetObject` bucket policy. Check the actual bucket policy/public-access settings, not just YAML. If the deployed layout differs, stop and review it; do not loosen IAM or signing to fit this runbook.
3. Apply only through the approved change process. Wait for CloudFront **Deployed**. For a previously cacheable distribution, inventory the old private routes (including legacy prefixes/aliases); invalidate affected entries under change control and wait for completion before enabling private playback. Do not use a whole-distribution invalidation as a test. Edge invalidation does not erase browser/proxy copies.
4. Run the read-only policy check with AWS CLI v2 and Python 3.9+ from the repo root. Supply the **expected** regional hostname for the API's bucket; do not use the origin returned by the distribution as proof it is the right one.

   ```sh
   python3 scripts/check_media_edge.py \
     --distribution-id "$STAGING_DISTRIBUTION_ID" \
     --origin-host "$STAGING_BUCKET_REGIONAL_DOMAIN" \
     --media-base-url "$MEDIA_BASE_URL" \
     --key-pair-id "$CLOUDFRONT_KEY_PAIR_ID"
   ```

   Only `cloudfront:GetDistribution`, `cloudfront:GetOriginAccessControl` and `cloudfront:GetResponseHeadersPolicy` are needed by this command. It reads no object, signing key or bucket policy and does not deploy or invalidate anything. It checks the ordered paths, actual cache/header policies, trusted key group, active public key and origin. It rejects unexpected routes rather than assuming another behavior is equivalent. A nonzero exit (including no credentials or incomplete output) means **not verified**.

## 2. Probe only known synthetic objects

Create small, uniquely named fixtures of known length and digest: one under each applicable private prefix and one under `audio/content/` as a cacheable catalog control. Use generated bytes, not a recording, transcript, Bible translation, checkpoint or existing listener job. Keep the bucket private. For the private fixtures, deliberately set **object metadata** to `Cache-Control: public, max-age=3600, immutable` like a legacy upload; confirm this independently with a privileged staging object HEAD. Do not edit a real object's metadata.

Obtain short-lived viewer URLs for the fixtures via the authorized staging playback path or the designated staging signer for the fixture keys only. Never add an API that signs arbitrary keys. Use a clean HTTPS client with no cookies, local/proxy cache or cloud credentials; disable redirect following, verbose traces and shell tracing. Keep signed URLs and bodies out of history, logs, screenshots and release tickets. Make fresh requests for each row; do not send cache-buster parameters.

| Check | Required observation |
| --- | --- |
| Valid signed private GET, then HEAD | `200`, expected digest/length (no body on HEAD); `Cache-Control: private, no-store` on both, **not** the legacy origin value. |
| Fresh signed `Range: bytes=0-7` on a private fixture larger than 8 bytes | `206`, correct `Content-Range` and the eight expected bytes; same private header. |
| Repeat the signed private GET at the same edge | Same authorized bytes and header, no `Hit`/`RefreshHit` or positive `Age` on the success responses. A single miss alone proves nothing; the zero-TTL policy in step 1 matters. |
| Warm the **catalog control** with signed GETs from the same edge | `200`, correct bytes; establish a real cache hit (e.g. `X-Cache: Hit from cloudfront`) before testing warm-cache denial. No observed hit means that check is inconclusive. |
| After successful reads, request each exact path unsigned, and with the fixture signature altered | CloudFront `403`, no fixture bytes, **including the warm catalog control**. Check a range request as well. No signed cookies. |
| After `Expires` (allow for clock skew), start new GET and range requests with the original signed URL | CloudFront `403`, no fixture bytes. A transfer begun before expiry may finish; it is not the expiry test. |
| Anonymous GET to the **regional S3 origin**, same known-existing keys, no presign | S3 `403`, no fixture bytes. A redirect, DNS error or `404` for an unknown key is not evidence of denial. |

Record the stack revision, timestamp, fixture classes, statuses, cache directives, edge hit/miss, byte comparisons and pass/fail only. Clean up the exact fixture objects, their versions and any cached catalog fixture under the approved retention/invalidation process. Do not sweep a prefix containing other objects. If a row fails or cannot be checked, keep private issuance gated and record the gap; do not fall back to a public URL or re-enable caching on private paths.

**Limits:** a policy change is not a recall of an issued URL, prior download or downstream copy. No object migration is implied. Direct private R2 presigning is a different deployment mode: use the [opt-in R2 staging playback check](R2-STAGING-PLAYBACK.md) rather than this distribution check. This procedure alone does not close [VE-007](OPEN-WORK-RECONCILIATION.md).
