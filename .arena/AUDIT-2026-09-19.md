## 2. The blocker: `main` was red

`gh run list` showed four consecutive failed runs, the two most recent on `main`
itself:

```
35455528016  failure  push    main  (merge of PR #38)   1m32s
35455514702  failure  pull_request  PR #37              1m40s
35448918621  failure  push    main  (merge of PR #36)   1m27s
35448875758  failure  pull_request  PR #36              1m35s
35445267515  success  push    main  (merge of PR #35)   2m25s
```

The failing step in run `35455528016` is `gofmt check`. Build, vet, test, design
tokens and lint all passed in that same job, so exactly one gate was red.

Consequence, and the reason this was treated as P0 rather than a style nit:
with `main` red, every subsequent pull request reports a failure that says
nothing about its own content. The signal that protects the branch was off.

## 3. Root cause, reproduced

`gofmt -l .` inside `server/` — the literal CI step — reported one file:

```
internal/api/home.go
```

The `recommendations` handler writes a response map whose keys were aligned for
a shorter key set. Keys are `"categories"`, `"confessions"`, `"count"` and
`"personalized"`; the alignment was one column short of the longest key, which is
what `gofmt` rewrites. The handler arrived with PR #36, and that pull request
merged while CI was already red, so the debt never had to be paid.

  sandbox artefacts and are never committed.
